*Generated 2026-11-01 from the module metadata in the fork and test scans on the live instance. Status describes the project, not any one person's account: a missing, rejected or exhausted API key is never counted as a failure.*

## How to read this

- **Type:** *API / web service* is a remote HTTP service; *Installed app* is a binary shipped in the container image; *Self-hosted service* needs your own instance URL; *Built-in* needs no external service.
- **Auth:** whether the module needs an API key (or instance URL) to do anything.
- **Cost / rate:** the pricing tag used in the UI (free, free tier, paid, local), the vendor model recorded in the module, and any built-in throttle or paging option (*module setting*). Vendors change free tiers often, so confirm limits on the linked site before relying on them.
- **Working:** ✅ produced results in real scans, or the tool is installed; 🔑 needs your own key or instance URL before it can be exercised; ❔ no key needed but not exercised yet; ⚠️ a scan hit a non-key error (service change, blocking, parse failure); ❌ the upstream service is gone or the tool cannot be installed.
